# 单图生 3D(腾讯混元生3D极速版)

用一张照片生成 3D 模型,再把结果丢进 Open3D 里看。
走的是腾讯云 API 3.0 的 **混元生3D极速版**:

| 用途 | Action | 文档 |
| --- | --- | --- |
| 提交任务 | `SubmitHunyuanTo3DRapidJob` | https://cloud.tencent.com/document/api/1804/123463 |
| 查询任务 | `QueryHunyuanTo3DRapidJob` | https://cloud.tencent.com/document/api/1804/123464 |

- 请求域名:`ai3d.tencentcloudapi.com`
- 版本:`2025-05-13`
- 地域:`ap-guangzhou`
- 任务结果 24 小时内有效;默认 1 个并发

常用参数:

| 参数 | 说明 |
| --- | --- |
| `--pro` | 走专业版,支持 `--view` 多视角 |
| `--view TYPE=PATH` | 附加视角,可重复:`left`/`right`/`back`;3.1 还支持 `top`/`bottom`/`left_front`/`right_front` |
| `--colmap-model` | COLMAP sparse 目录;按相机位姿自动选图并提交(见 5.4) |
| `--auto-view-types` | 自动选视角类型,默认 `front,left,right,back` |
| `--size-weight` | 选图时「目标大而完整」的权重(度),默认 15;0=只看角度 |
| `--border-penalty` | 目标贴画面边缘时质量打折比例,默认 0.5 |
| `--front-image` | 自动选图时固定某张当 front |
| `--dry-run` | 只选图 + 编码,不调用 API |
| `--model-version` | 专业版 `3.0`(默认)/`3.1` |
| `--format` | 极速版默认 GLB;专业版默认 obj+glb,只有 STL/USDZ/FBX 需要显式指定 |
| `--pbr` | 开启 PBR 材质 |
| `--geometry` | 只要白模(无纹理) |
| `--timeout` | 轮询超时,默认 900 秒 |
| `--interval` | 轮询间隔,默认 5 秒 |

## 4. 输入限制

- `ImageBase64` / `ImageUrl` / `Prompt` 三选一,不能同时给图片和提示词
- 图片单边分辨率 128 ~ 5000
- Base64 方式图片 ≤ 6 MB(编码后大约 +30%)
- URL 方式 ≤ 8 MB
- 支持 jpg / png / jpeg / webp

脚本默认把本地图片转 Base64 发过去,不用先传到 COS。

## 5. 先分割再生成(SAM3 → 白底抠图 → 多视角)

直接拿带天空、地面、树木的原图去生成,背景会被当成物体的一部分。更稳的做法是
先用 SAM3 把目标抠出来,再白底合成:

```

        ▼

        │  mask_cutout.py
        ▼
   out\sceaux_cutouts\*.jpg      白底、裁到物体、补正方形、统一 1024
        │  img_to_3d.py --pro --view ...

   Open3D
```

极速版只能收**一张**图。专业版 `SubmitHunyuanTo3DProJob` 的 `MultiViewImages`
可以再带 `left`/`right`/`back`(3.1 还支持 `top`/`bottom`/`left_front`/`right_front`),
主图 `--image` 就是前视图。

```powershell

  --pro --model-version 3.0 `
  --image "out\sceaux_cutouts\100_7104.jpg" `
  --view left="out\sceaux_cutouts\100_7101.jpg" `
  --view right="out\sceaux_cutouts\100_7108.jpg"
```

### 5.4 用相机位姿自动选 front/left/right/back

照片是绕物体拍的时候,COLMAP 已经知道每张相机的位姿,不必手工猜哪张是左、
哪张是右。`tools\colmap_views.py` 会:

1. 读 `images.bin`,算相机中心 `C = -R^T t`;
2. 用点云最大平面(桌面/地面)的法向当 up;
3. 用 `labels.npy` 里目标类别的质心当物体中心 `O`;
4. 把 `C-O` 投影到水平面,算每张图的方位角;
5. 穷举「哪张当 front、其余怎么分配给 left/right/back」,按
   **方位误差 + 图片质量**打分:质量由目标在照片里的占比(越大越好)
   和是否贴边被裁(贴边打折)决定,所以不会为了 1° 的角度差去选
   一张物体很小/被裁掉的照片。`--size-weight` 默认 15(折合度数),
   设 0 就退回纯角度选择。

cup 场景(7 张注册图)实测:


3.1 想多用几张,可以加斜前视角(最多 8 视图):

```powershell
& "C:\Users\FANLS\.conda\envs\basic_env\python.exe" "tools\img_to_3d.py" `
  --pro --model-version 3.1 --colmap-model "work\cup\dense\sparse" `
  --auto-view-types front,left_front,left,right_front,right,back
```

注意:

- **主图就是 front**,其余标签是相对主图实际方位算的;不要用「整体旋转一下
  让误差更小」的办法,因为接口不会跟着转。
- 左右约定:`+90° = 物体左侧`(相机在物体左边)。如果发现左右反了,
  加 `--swap-left-right`。
- 没有真正的背面时,会选最接近 180° 的图,`误差` 列会标出来。
- 想固定某张当前视图,用 `--front-image 文件名`。
- 没有 `labels.npy` 时用相机光轴交点当物体中心;没有点云时 `--up camera`。
  cup 这种桌面场景默认的 plane up 最准。

## 6. Open3D 显示说明

Open3D 显示网格时**不显示贴图**,只认顶点色。所以脚本先用
trimesh 加载 GLB/OBJ,把纹理逐顶点采样成顶点色,再转成
`o3d.geometry.TriangleMesh`:

- 贴图采样成功 → 带颜色的模型
- 采样几乎全黑(有些 GLB 的 UV 是按面存的)→ 自动退回白模
- 窗口操作:左键拖动旋转,滚轮缩放,中键平移,`Q` 退出

另外两个坑,脚本里已经处理:

- **坐标轴**:混元输出是 Y 轴朝上(glTF 惯例),脚本统一转到 Z 轴朝上,
  否则模型是躺着的。
- **渲染后端**:`o3d.visualization.rendering.OffscreenRenderer`(Filament/Vulkan)
  在 47 万面的混元模型上会整帧输出全黑(连背景都黑),换成旧版
  `Visualizer`(OpenGL)就正常。所以 `--screenshot` 和弹窗用的是同一个
  `Visualizer`,截图不需要额外开离屏渲染。
