# 生成模型 × 重建点云配准

把「图生 3D」生成的模型,配准到同一场景用 OpenMVS 重建出来的点云上,
在一个 Open3D 窗口里叠加显示:SAM3 标出的点按类别染色,
多张照片的相机位置用黄色四棱锥画出来。一次可以配准多个物体。

**工具**:`tools\register_model_to_cloud.py`
**数据**(Sceaux,2026-10-21 实测):
- 点云:`work\sceaux\mvs\scene_dense.ply`(465,563 点)
- 模型:`work\img2_3d\1504329910981484544\*.glb`(322,942 顶点 / 469,314 面)
- 标签:`out\sceaux_labels.npy`(SAM3 `building`,带置信度)

---

## 一、整体流程

```
work\sceaux\mvs\scene_dense.ply          重建点云
        │  mask_to_points.py + masks_sceaux
        ▼
out\sceaux_labels.npy                    每点一个类别(1 = building)
        │
        ├──────────────┐
        ▼              ▼
   建筑点(配准目标)   全部点(显示,建筑=青色)
        │
        │   混元模型 .glb(带贴图)
        ▼              │
   ┌───────────────────┘
   ▼
宽度定尺度 → 搜 ±20° yaw → 包围盒居中 → 轮廓 F1 选最优 → 深度对齐
   │
   ▼
out\sceaux_registered.ply                点云 + 模型采样点,合并成一个 ply
```

## 二、坐标轴和尺度(最容易错的地方)

1. **点云是 Y 轴朝下**。从 `images.bin` 的相机位姿算出来:平均 up 向量是
   `(0.034, -0.997, -0.023)`,即世界 −Y 朝上;相机看向 +Z。
   脚本先把点云绕 X 轴转 −90°(`ROT_UP`),统一成 **Z 轴朝上**。
2. **模型是 Y 轴朝上**(glTF 惯例),`img_to_3d.load_mesh_with_colors`
   里已经转了 Z-up。
3. 转完之后:
   - 模型主立面朝 **−Y**,点云拍摄面也朝 **−Y**;
   - 两边只差一个绕 Z 的小角度和尺度。
4. **尺度差约 10.8 倍**:点云建筑宽 8.56,模型宽 0.794。
   Open3D 的 RANSAC 只估旋转+平移,不估尺度,必须先缩放。

---

## 三、为什么最终位姿不是 RANSAC 给的

这条点云几乎只有**正立面**,近似一个平面。3D 配准沿立面方向是病态的:
FPFH+RANSAC 和 ICP 都可以把模型沿墙面滑一段,`fitness` 仍然很高。
实测:

| 位姿来源 | 现象 |
| --- | --- |
| RANSAC + ICP | 模型整体滑向一侧,或缩到点云轮廓里 |
| 包围盒居中 + 宽度尺度 | 位置稳定,但 yaw 还可能差几度 |

所以工具采用「已知坐标系 + 轮廓对齐」作为最终位姿:

- **尺度**:只用立面宽度比 `ΔX_cloud / ΔX_model`。不用高度/进深——
  模型只见过三张正面图,进深是生成的,和真实建筑差很多。
- **yaw**:在 ±20° 内搜,用立面投影(X-Z)的**轮廓 F1** 选:
  `F1 = 2PR/(P+R)`,`P` = 模型格子里落在点云轮廓内的比例,
  `R` = 点云格子被模型覆盖的比例。不用 IoU:模型缩小后整个躲在
  点云轮廓里,IoU 会被 union 稀释,反而偏向「越小越好」。
- **平移**:两边包围盒中心对齐;最后沿 Y 做一次深度对齐。
- **深度参考**(`--depth-ref`):
  - `median`(默认):模型正面贴到点云深度的中位数。这条点云只有
    立面,用中位数才能让约一半点云显示在模型前面,窗口里两边都看得见。
  - `front`:贴到最靠近相机的 5%。更接近「物理表面」,但会让模型挡住
    95% 的点。

RANSAC / ICP 仍然会跑,指标打印出来做对照;加 `--use-icp` 才让它参与
选位姿。

## 四、命令

先给点云打标签(如果没有现成的 `labels.npy`):

```powershell
$py   = "C:\Users\FANLS\.conda\envs\basic_env\python.exe"
$root = "D:\code\point_cloud\0916"

& $py "$root\tools\mask_to_points.py" `
  --scene "$root\work\sceaux\dense\sparse" `
  --mask-dir "$root\masks_sceaux" --mask-mode index --class-names building `
  --out "$root\out\sceaux_masked.ply" `
  --out-all "$root\out\sceaux_all_labeled.ply" `
  --labels "$root\out\sceaux_labels.npy" `
  --save-npz "$root\out\sceaux_full.npz"
```

配准 + 显示:

```powershell
& $py "$root\tools\register_model_to_cloud.py" `
  --cloud "$root\work\sceaux\mvs\scene_dense.ply" `
  --labels "$root\out\sceaux_labels.npy" `
  --npz "$root\out\sceaux_full.npz" `
  --mesh "$root\work\img2_3d\1504329910981484544\d4bc1683-...-0.glb" `
  --colmap-model "$root\work\sceaux\dense\sparse" `
  --out-merged "$root\out\sceaux_registered.ply"
```

`--colmap-model` 会读 `images.bin`,在窗口里给每张照片画一个黄色四棱锥。
不写也行:工具会从 `--cloud` 自动推出 `<场景>\dense\sparse`。
不要相机显示时加 `--no-cameras`。

不弹窗只看截图:

```powershell
& $py "$root\tools\register_model_to_cloud.py" ... `
  --no-show --screenshot "$root\work\diag\register.png"
```

手动指定尺度 / 让 ICP 参与:

```powershell
& $py ... --scale 10.5 --use-icp
```

### 桌面物体(cup):`--mode object --up-axis auto`

上面的默认值都为「建筑正立面」设计:点云 Y 轴朝下、只搜 ±20° yaw、用立面投影
的轮廓 F1 打分。杯子这种放在桌上的独立物体三样都不成立,要换一组参数:

```powershell
& $py "$root\tools\register_model_to_cloud.py" `
  --cloud "$root\work\cup\mvs\scene_dense.ply" `
  --labels "$root\out\cup_labels.npy" --npz "$root\out\cup_full.npz" `
  --mesh "$root\work\img2_3d\1504473474843754496\56d57335-....glb" `
  --mode object --up-axis auto `
  --out-merged "$root\out\cup_registered.ply" `
  --screenshot "$root\work\cup_register.png"
```

- `--up-axis auto`:RANSAC 拟合最大平面(桌面),把桌面法向转到 +Z。
  **建筑不要用**,建筑点云的最大平面是墙,不是地面。
- `--mode object`:绕 Z 搜 360°,每个 yaw 做一次 ICP,用 3D 对称 Chamfer
  选最优;不做「立面深度对齐」。
- 标注点少于 1000 时自动跳过统计滤波 —— cup 实测 205 个点,滤波会把稀疏的
  杯身当离群点删掉,尺度从 1.23 塌成 0.46。

cup 实测:尺度 1.088、Chamfer 0.1934、RMSE 0.0321、合并 389,216 点、3.7 s。

### 多个物体:一次配准两个模型

`--mesh` 可以重复,写成 `类别id=路径`。每个类别独立配准(各自用自己的
labels 子集、自己的尺度和位姿),最后合并到同一个 ply、同一个窗口:

```powershell
& $py "$root\tools\register_model_to_cloud.py" `
  --cloud "$root\work\cup\mvs\scene_dense.ply" `
  --labels "$root\out\cup_labels.npy" --npz "$root\out\cup_full.npz" `
  --mesh "1=$root\work\img2_3d\<JobId1>\cup.glb" `
  --mesh "2=$root\work\img2_3d\<JobId2>\bottle.glb" `
  --mode object --up-axis auto `
  --colmap-model "$root\work\cup\dense\sparse" `
  --out-merged "$root\out\cup_registered.ply" `
  --save-transform "$root\out\cup_registration.json"
```

- 类别 id 必须和 `mask_to_points.py --class-names "cup,bottle"` 的顺序一致
  (1=cup,2=bottle)。
- 点云颜色:类别 1 青、类别 2 橙、类别 3 品红、类别 4 绿,其余保留照片色。
- 合并 ply 里每个模型各采样 `--merge-points`(默认 20 万)个点。
- `--save-transform` 的 json 里 `objects` 是数组,每个物体一项;
  只有一个物体时顶层仍然保留原来的 `scale` / `transform_4x4` 等字段。
- `--scale` 是全局手动尺度,多物体时慎用(会作用到所有模型)。

## 五、参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--cloud` | 必填 | 重建点云 `.ply` |
| `--mesh` | 必填 | 混元生成的 `.glb/.obj`;可重复,多物体写 `类别id=路径` |
| `--labels` | — | `mask_to_points.py` 的 `labels.npy` |
| `--npz` | — | `mask_to_points.py --save-npz` 的结果(用 confidence 过滤) |
| `--class-id` | `1` | 要配准的类别 id |
| `--min-conf` | `0.9` | 目标点最低置信度;`0` = 不过滤 |
| `--scale` | 自动 | 手动尺度;默认立面宽度比 |
| `--mode` | `facade` | `facade` 建筑立面 / `object` 独立物体(360° yaw + Chamfer) |
| `--up-axis` | `y-down` | `y-down` / `auto`(拟合最大平面)/ `z` / `x,y,z` |
| `--yaw-range` | 20 / 360 | yaw 搜索半角;facade 默认 20,object 默认 360 |
| `--yaw-step` | 5 / 15 | yaw 步长;facade 默认 5,object 默认 15 |
| `--scale-axis` | `x` / `max` | 尺度方向;facade 默认 x(立面宽),object 默认 max |
| `--voxel` | 自动 | 配准用体素,默认建筑最大边长的 1/80 |
| `--depth-ref` | `median` | `median` / `front`,见第三节 |
| `--no-depth-align` | 关 | 不做深度对齐 |
| `--use-icp` | 关 | 让 RANSAC/ICP 参与选位姿 |
| `--cloud-colors` | `keep` | `keep` 保留点云原始照片色(目标类别仍染色)/ `gray` 其余点全灰 |
| `--colmap-model` | 自动 | COLMAP sparse 目录;默认从 `--cloud` 推 `<场景>/dense/sparse`,画相机位姿 |
| `--no-cameras` | 关 | 不画相机四棱锥 |
| `--camera-scale` | `0.05` | 相机四棱锥大小,场景对角线的比例 |
| `--display-voxel` | `0` | 窗口点云降采样体素;`0` = 不降采样(全量显示);`>0` 指定体素;`-1` = 按目标最大边长 1/100 自动 |
| `--display-offset` | `0` | 点云朝相机挪动的比例(场景对角线) |
| `--out-merged` | — | 合并后的点云 `.ply` |
| `--save-transform` | — | 4×4 变换矩阵存 json |
| `--screenshot` | — | 叠加截图 |
| `--no-show` | 关 | 不弹窗 |

## 六、输出

| 文件 | 内容 |
| --- | --- |
| `out\sceaux_registered.ply` | **合并点云**:前 465,563 个是场景点(建筑青色、其余保留点云原始照片色),后 200,000 个是模型采样点(保留贴图颜色) |
| `--screenshot` 指定的 png | 窗口同款视角的叠加截图(含黄色相机四棱锥) |
| `--save-transform` 指定的 json | `objects`(每个物体的 scale + 4×4 矩阵 + 指标)、`cameras`(相机中心) |

合并 ply 在 MeshLab / CloudCompare 里打开就能看到两套点交错在一起;
点云顺序没有裁剪/排序,所以标签仍然对得上。

点云颜色默认 `--cloud-colors keep`:目标类别染青色,其余点用 OpenMVS 从照片带出来的
真实颜色(桌面、墙面、地面都保持原色),窗口显示和合并 ply 是同一套配色。
点云本身没有颜色时自动退回灰色;想强制全灰用 `--cloud-colors gray`。

## 七、坑

| # | 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| 1 | 点云把模型完全盖住 | 点云 46 万点在 1280×800 里约每像素 2 个 | 默认不再降采样(全量显示);盖住时加 `--display-voxel -1` 自动或 `--display-voxel 0.01` 手动降采样,合并 ply 始终是全量 |
| 2 | 模型缩得很小 | 用轮廓 IoU 或进深比选尺度 | 用立面宽度比;轮廓用 F1 不用 IoU |
| 3 | 模型滑到一边 | 正立面近似平面,ICP/RANSAC 沿墙滑动不解 | 默认不让 ICP 参与;需要时 `--use-icp` |
| 4 | 模型贴反了(看到的是背面庭院) | 误以为要转 180° | 两个主立面都朝 −Y,不需要翻 |
| 5 | 窗口里相机方向反了 | Open3D `set_front` 传的是**从物体指向相机**的方向,不是视线方向 | `show()` 里传 `(-0.15, -1, 0.12)` |
| 6 | 点云旋转后位置不对 | `pc.rotate(R)` 不传 center 时是绕几何中心转,不是原点 | 显式 `center=(0,0,0)` |
| 7 | PowerShell 里中文/⚠ 报编码错 | 默认 stdout 是 GBK | 脚本已 `reconfigure(encoding="utf-8")` |
| 8 | 窗口里没有相机四棱锥 | 没找到 `images.bin` | 显式 `--colmap-model <场景>\dense\sparse` |
| 9 | 两个物体配准到同一个点集 | `--mesh` 没写类别 id | 写成 `--mesh 2=xxx.glb`,id 对应 labels 类别 |

## 八、实测结果(Sceaux)

```
点云          465,563 点
配准目标      385,264 点(类别 1,conf ≥ 0.9)→ 统计滤波后 374,178
建筑包围盒     8.555 × 4.425 × 4.502(1-99%)
模型包围盒     0.7937 × 0.7848 × 0.5165
尺度          10.778(立面宽度比)
yaw           +5°(轮廓 F1 = 0.792,±20° 范围内差异 0.74~0.79)
深度对齐       median(y=10.14),沿 +Y 平移 3.91
合并 ply       665,563 点 / 17.9 MB
耗时           约 5.5 s(不含标签)
```

RANSAC/ICP 的对照指标(同一尺度,yaw 0):

| 方法 | 正向覆盖 | 反向覆盖 | 结果 |
| --- | --- | --- | --- |
| FPFH + RANSAC(400k 次)+ ICP | 0.10 | 0.30 | 沿立面滑向一侧 |
| 宽度尺度 + 包围盒居中 | — | — | 位置稳定,叠加正常 |

> 覆盖率低不代表位姿错:生成模型和重建点云的几何细节本来就对不上
> (窗户、屋顶轮廓都不是同一份数据),3D 距离指标天然偏低。
> 最终以叠加截图的轮廓是否对齐为准。
