# OpenMVS 三维重建 — 流程与产物手册

图像 → 带纹理三维模型。全程 **CPU**,Windows + PowerShell。

**本文档所有命令和数字都来自实测**(数据集:`data\food`,13 张 `.JPG`,2026-09-17 跑通)。

---

## 0. 一句话流程

```
图像/视频 → COLMAP 算相机位姿 → InterfaceCOLMAP 转工程 → OpenMVS 稠密重建/网格/纹理 → glb
```

**OpenMVS 不做 SfM**。相机位姿和稀疏点云必须由上游 COLMAP 提供,`InterfaceCOLMAP` 是两者之间的桥。

### 第 1 步:定义变量 + 建目录

```powershell
$W   = "D:\code\point_cloud\0916\work\food"
```

---

### 第 2 步:COLMAP 特征提取

```powershell
colmap feature_extractor --database_path "$W\db.db" --image_path "$IMG" --ImageReader.single_camera 1 --FeatureExtraction.use_gpu 0 --FeatureExtraction.max_image_size 2000
```

**产物:** `$W\db.db`(COLMAP 数据库,含每张图的 SIFT 特征)

**怎么看:** 终端会逐张打印 `Processing file [n/m]`。**留意有没有 `CAMERA_SINGLE_DIM_ERROR` 警告。**

**注意:**
- `--FeatureExtraction.use_gpu 0` **必须显式传**。nocuda 版没编 GPU 代码,但默认值仍是 `1`,不传会直接报错。
- 参数名是 COLMAP 4.2 的新名字。旧教程里的 `--SiftExtraction.max_image_size` 已失效。
- `--max_image_size 2000` = 超过 2000px 的图先缩小,提速明显。

---

### 第 3 步:特征匹配

```powershell
colmap exhaustive_matcher --database_path "$W\db.db" --FeatureMatching.use_gpu 0
```

**产物:** 写回 `$W\db.db`(匹配关系)

**怎么看:** 终端打印 `Matching block [n/m]`。13 张图几分钟内跑完。

**注意:**
- 图像少(<200 张)用 `exhaustive_matcher`,最准。
- 图像多(>200 张)改 `colmap sequential_matcher --database_path "$W\db.db" --FeatureMatching.use_gpu 0 --SequentialMatching.overlap 10`,快很多。
- `--FeatureMatching.use_gpu 0` 同样必须显式传。

---

### 第 4 步:稀疏重建(SfM)

```powershell
colmap mapper --database_path "$W\db.db" --image_path "$IMG" --output_path "$W\sparse"
```

**产物:** `$W\sparse\0\` 目录,里面四个文件:

| 文件 | 内容 |
|---|---|
| `cameras.bin` | 相机内参 |
| `images.bin` | **每张图的位姿**(位置 + 朝向) |
| `points3D.bin` | 稀疏点云 |
| `project.ini` | 工程配置 |

**怎么看:**

```powershell
colmap model_analyzer --path "$W\sparse\0"
```

输出里 `Registered images` 就是成功注册的图像数。**13 张图期望注册 13 张。**

**注意:**
- 如果 `$W\sparse\` 下出现了 `0` `1` `2` 多个子目录 → 场景断成了多块。用注册图像最多的那个,后面所有 `sparse\0` 改成对应编号。
- `project.ini` 可以直接用记事本打开,里面有每张图的位姿和重投影误差。

---

### 第 5 步:图像去畸变

```powershell
colmap image_undistorter --image_path "$IMG" --input_path "$W\sparse\0" --output_path "$W\dense" --output_type COLMAP
```

**产物:** `$W\dense\`

| 文件 | 内容 |
|---|---|
| `images\` | **去畸变后的图像**(原图的副本,尺寸可能变) |
| `sparse\` | 对应的位姿 |
| `stereo\` | 立体匹配配置 |

**怎么看:** 打开 `$W\dense\images\`,和原图对比 —— 直线应该更直(镜头畸变被拉平了)。

**注意:** 这一步文件大小翻倍(每张图存了一份副本),磁盘要留够。

### 第 6 步:转成 OpenMVS 工程

```powershell
InterfaceCOLMAP -i "$W\dense" -o "$W\mvs\scene.mvs" --image-folder "$W\dense\images" -w "$W\mvs"
```

**产物:** `$W\mvs\scene.mvs`(实测 13 图 = 313 KB)

**怎么看:**

```powershell

```

打开后能看到**一堆小金字塔形状(相机视锥)+ 稀疏点云**。

**⚠️ 这是最关键的人工检查点。** 相机应该围着物体排成一圈/一圈半;如果有相机乱飞、或者只有两三台相机、或者点云散成一团 —— 别往下跑了,稠密重建只会更糟。先回头查图像重叠度。

**注意:** OpenMVS 的日志写在同目录,文件名叫 `InterfaceCOLMAP-<时间戳>.log`。终端不打印任何东西是正常的。

### 第 8 步:网格重建

```powershell
ReconstructMesh scene_dense.mvs -p scene_dense.ply -o scene_dense_mesh.ply
```

**产物:** `scene_dense_mesh.ply`(实测 **29.87 MB / 824422 顶点 / 1648306 面**,耗时约 24.5 秒)。

日志关键行:

```
[PointCld] Point-cloud 'scene_dense.ply' loaded: 1112606 points (276ms)
[Mesh    ] Delaunay tetrahedralization completed: ... (4s323ms)
[ScnRecnt] Delaunay tetrahedras graph-cut completed (1.25978e+06 flow): 824684 vertices, 1649657 faces
[Mesh    ] Mesh 'scene_dense_mesh.ply' saved: 824422 vertices, 1648306 faces
```

**⚠️ `-p` 是「输入稠密点云」,不是「输出网格」。**

```
-p [ --pointcloud-file ] arg   dense point-cloud with views file name to reconstruct
-o [ --output-file ] arg       output filename for storing the mesh
```

写成 `-p scene_dense_mesh.ply`(把网格文件名传进去)**不会报错**,而是静默退回
`scene_dense.mvs` 里那 6015 个稀疏点:

```
[Delaunay] Delaunay tetrahedralization completed: 6015 points     ← 少了三个数量级
```

于是只得到 **2621 顶点 / 5132 面**(97 KB)的粗模。**这才是这个文件以前被记成
"97 KB / 精简过的网格"的原因 —— 不是它精简,是它根本没吃到稠密点云。**

**自检:** 日志里 `Point-cloud '...' loaded:` 那行的点数必须是**百万级**。

**怎么看:**

```powershell
& "D:\code\point_cloud\0916\OpenMVS_Windows_x64\vc17\x64\Release\Viewer.exe" "$W\mvs\scene_dense_mesh.ply"
```

### 第 10 步:纹理贴图

先搞清楚参数,这里最容易踩坑:

```
-o [ --output-file ] arg    output filename for storing the **mesh**
--export-type arg (=ply)    file type used to export the 3D scene   ← 格式由它决定
```

**`-o` 只是网格的文件名,格式由 `--export-type` 决定(默认 ply)。TextureMesh 不写 `.mvs` 工程文件** —— 传 `-o scene_textured.mvs` 只会得到一个叫这名字的 `.ply`。

### ★★ 必须关掉 seam leveling ★★

```powershell
--global-seam-leveling 0 --local-seam-leveling 0
```

默认 `--global-seam-leveling 1 --local-seam-leveling 1` 在本机这个 v2.4.0 构建上,
会把**面自己的 texel** 整片涂成黑/红/绿标记色,只留下向外的膨胀(dilation)光晕 ——
而 UV 恰好只覆盖面自己的 texel,于是打开模型只见**橙黑两色**。

同一份场景、同一份网格,只改这两个开关:

| 选项 | 图集纯黑 | 图集真内容 | 网格 UV 落在真照片上 | UV 处中位亮度 |
|---|---|---|---|---|
| 默认 | 24.3% | 20.4% | 2.9% | 0.0 |
| 只关 `--global-seam-leveling 0` | 24.5% | 20.2% | 0.8% | 0.0 |
| 只关 `--local-seam-leveling 0` | 5.1% | 39.6% | 83.0% | 94.0 |
| **两个都关** | **0.0%** | **64.7%** | **100.0%** | **115.3** |

**主犯是 local**,global 也贡献一小部分,一起关最干净。

旁证:开 seam leveling 时 1648306 个面被切成 **112897 个 patch**(平均 15 面/patch),
关掉后只剩 **12605 个**(平均 131 面/patch),差 9 倍 —— 它当时就是在面级别乱切。

**代价:** 关掉后少了 patch 之间的颜色匀色,接缝处可能看得出色差。但比整片黑强得多。

**另一个坑:`--ignore-mask-label -2`(想关掉 mask)在本机构建上直接段错误,别用。**

**出法 A —— 带纹理的 ply(能在 Viewer 里看):**

```powershell
TextureMesh scene_dense.mvs -m scene_dense_mesh.ply -o scene_textured.ply --global-seam-leveling 0 --local-seam-leveling 0
```

产物:`scene_textured.ply`(69.17 MB)+ `scene_textured0.png`(62.95 MB)。

**出法 B —— glb(交付格式):**

```powershell
TextureMesh scene_dense.mvs -m scene_dense_mesh.ply --export-type glb --global-seam-leveling 0 --local-seam-leveling 0
```

没传 `-o` 时,输出名自动取「输入场景名 + `_texture`」。输入是 `scene_dense.mvs`,所以产物是:

| 文件 | 实测大小 | 内容 |
|---|---|---|
| `scene_dense_texture.glb` | 36.74 MB | 几何数据(内嵌) |
| `scene_dense_texture_0.png` | **63.06 MB** | 纹理贴图(**外链**) |

**⚠️ glb 不是单文件!** 实测 glb 内部是这样的:

```json
"images": [ { "name": "scene_dense_texture_0", "uri": "scene_dense_texture_0.png" } ]
```

几何数据嵌在 glb 里,纹理指向旁边的 png。**这两个文件必须一起拷贝**,单独把 glb 拿走会得到个没贴图的白模。

换 `--export-type obj` 可出 OBJ(含 mtl + 贴图)。

**怎么看:** 见下一节 —— **Viewer 打不开 glb**。

## 5. 踩过的坑(实测记录)

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| 1 | `unrecognised option '--SiftExtraction.xxx'` | COLMAP 4.2 把顶层参数改名了 | 改用 `--FeatureExtraction.xxx` / `--FeatureMatching.xxx` |
| 2 | `use_gpu` 相关报错 | nocuda 版没编 GPU 代码,但默认值仍是 1 | 必须显式传 `--FeatureExtraction.use_gpu 0` 和 `--FeatureMatching.use_gpu 0` |
| 3 | `Check failed: ExistsDir(*image_path)` | `$IMG` 多写了一层 `\images` | 填图像**所在地那一层** |
| 4 | `CAMERA_SINGLE_DIM_ERROR` 警告 | `single_camera 1` 要求尺寸一致,混进了竖拍图 | 把尺寸不同的图移走,或去掉 `single_camera 1` |
| 5 | `-o scene_textured.mvs` 得到的是 `.ply` | `-o` 是网格文件名,格式由 `--export-type` 定;TextureMesh 不写 `.mvs` | 要 glb 就用 `--export-type glb` |
| 6 | Viewer 打不开 glb: `invalid project` | Viewer 不能导入 glTF | 用 `.mvs` / `.ply` 看;glb 用 Blender 看 |
| 7 | 交付的 glb 在别人机器上是白模 | glb 的贴图是**外链**的 png | glb 和 `*_0.png` 一起给 |
| 8 | `no kernel image is available` | CUDA 架构不匹配(sm_89 vs sm_120) | 用 CPU 版 |
| 9 | mapper 之后 `sparse\` 下有 `0` `1` 多个目录 | 场景断成多个子模型 | 用注册图像最多的那个 |
| 10 | OpenMVS 命令跑完终端没输出 | 正常,日志写在同目录 `.log` | 看 `*-<时间戳>.log` |
| 11 | 模型形状不对 / 缺一大块 | 图像重叠不足 | 提高抽帧率、降低 `max_image_size`、或改用 `exhaustive_matcher` |
| 12 | 没有绝对尺度和真实坐标 | 没有 GPS EXIF,重建结果是任意尺度 | 需要真实尺寸就在场景里放已知大小的标定物 |
| 13 | 单航带直线飞行重建失败 | 相机中心共线,滚转角无法约束 | 用往复式(割草机式)航线、环绕拍摄或高度变化 |

## 6. 换一组数据

**结果自动保留,不用做任何事** —— 工作目录按场景名隔离:

```
work\
├── sceaux\      ← 旧结果原封不动
├── food\        ← 各自独立一份
└── <新场景名>\
```

**只需改第 1 步的两个变量**,然后从第 1 步往下跑:

```powershell
$W   = "D:\code\point_cloud\0916\work\mynewdata"          # 新场景名
$IMG = "D:\code\point_cloud\0916\data\mynewdata"          # 新图像目录
New-Item -ItemType Directory -Force -Path "$W\sparse","$W\dense","$W\mvs" | Out-Null
cd $W
```

**三条注意:**
1. **绝不要复用同一个场景名** —— `$W` 指向已有目录时,第 4 步 `mapper` 会因为 `sparse\0` 已存在而报错或产出混乱。
2. **路径不要有中文和空格** —— COLMAP 对非 ASCII 路径支持不好。
3. **磁盘留够** —— 总占用 ≈ 原图总量 × 2(去畸变副本)+ 图像数 × 50 MB(深度图)。

## 7. 流程原理速览

```
图像
   │ ① COLMAP feature_extractor   每张图找 SIFT 特征
   │ ② COLMAP exhaustive_matcher  找图与图之间的同名点
   │ ③ COLMAP mapper              增量式 SfM → 相机位姿 + 稀疏点云
   │ ④ COLMAP image_undistorter   去镜头畸变
   ▼
去畸变图像 + 位姿
   │ ⑤ InterfaceCOLMAP           → OpenMVS .mvs 工程      ← 两者之间的桥
   ▼
scene.mvs
   │ ⑥ DensifyPointCloud         PatchMatch 逐视图算深度图 → 融合成稠密点云
   ▼
scene_dense.ply
   │ ⑦ ReconstructMesh           点云 → 三角网格
   │ ⑧ RefineMesh                优化网格、恢复细节
   │ ⑨ TextureMesh               从原图给网格上色
   ▼
glb / ply → 查看或交付
```

视频输入的话,在 ① 之前加一步 ffmpeg 抽帧:

```powershell
ffmpeg -i "input.mp4" -vf "fps=2,scale='min(2000,iw)':-2" -q:v 2 "images\frame_%05d.jpg"
```

## 8. 已知限制

1. **无 GPU 加速**,稠密重建慢。数据量大时优先调 `--resolution-level`(每 +1 快约 4 倍)。
2. **无真实尺度**(见第 5 节第 12 条)。
3. **没有 `CreateStructure` / `ExtractKeyframes`** —— 这两个是 OpenMVS `develop` 分支的新功能,不在 v2.4.0 预编译包里,要自己编源码才能用。所以 SfM 必须外接 COLMAP,视频抽帧必须外接 ffmpeg。
4. **Viewer 不能导入 glTF** —— 看模型只能用 `.mvs` / `.ply`。
