
# 全流程:照片 → 点云 → SAM 分割 → 多视角生 3D → 配准叠加

从一组绕物体拍的照片,一直做到「生成的模型和重建点云在同一个 Open3D 窗口里,
并且看得到每张照片的相机位置」。

命令全是 PowerShell,适用于任意项目路径、任意物体;一次可以处理 **1~N 个物体**
(每个物体一个 SAM3 提示词 / 一个类别 id / 一个混元任务)。

**你只需要在开头改两行:项目根目录、要分割的物体名称列表。**

```
<照片目录>\*.jpg
    │  ①-⑤ COLMAP               SIFT → 匹配 → SfM → 去畸变
    ▼
<root>\work\<场景>\dense\        去畸变图 + 位姿
    │  ⑥-⑧ OpenMVS             转工程 → 稠密点云 → 网格
    ▼
<root>\work\<场景>\mvs\scene_dense.ply
    │  ⑨-⑩ SAM3(多提示词)+ mask_to_points
    ▼
<root>\out\<场景>_labels.npy     每点一个类别(1,2,...)
    │  ⑪ mask_cutout            按类别分别白底抠图
    ▼
<root>\out\<场景>_cutouts_<物体>\*.jpg
    │  ⑫ colmap_views.py        按相机位姿 + 图片大小/完整性选视角
    ▼
<root>\out\<场景>_views_<物体>.json
    │  ⑬ img_to_3d.py --pro     每个物体单独提交混元多视角生 3D
    ▼
<root>\work\img2_3d\<JobId>\*.glb
    │  ⑭ register_model_to_cloud.py   多模型配准 + 相机位姿显示
    ▼
<root>\out\<场景>_registered.ply + Open3D 窗口
```

## 0. 开头只改这里

```powershell
# ===================== 只改这两行 =====================
$root = "D:\code\point_cloud\0916"      # 项目根目录
$objs = @("black travel mug", "whitetravel mug")               # SAM3 提示词,1~N 个;类别 id 依次 1,2,...
# ======================================================

# 场景名:默认第一个物体;照片文件夹叫别的名字时改这一行
$scene = "cup2"

# 图片目录:默认 <root>\data\<场景>;照片在别处时改这一行
$IMG = "$root\data\$scene"

# ---- 下面都是推导出来的,不用改 ----
$py    = "C:\Users\FANLS\.conda\envs\basic_env\python.exe"
$sam   = "D:\ProgramData\anaconda3\envs\sam3\python.exe"
$W     = "$root\work\$scene"
$MVS   = "$W\mvs"
$masks = "$root\masks_$scene"
$out   = "$root\out"
$names = $objs -join ","

# 每个物体一个抠图目录;只有一个物体时沿用 <场景>_cutouts
$cutouts = @{}
for ($i = 0; $i -lt $objs.Count; $i++) {
    $cutouts[$objs[$i]] = if ($objs.Count -eq 1) {
        "$out\${scene}_cutouts"
    } else {
        "$out\${scene}_cutouts_$($objs[$i])"
    }
}
```

| 变量                                                                         | 含义                                                    | 默认值         |
| ---------------------------------------------------------------------------- | ------------------------------------------------------- | -------------- |
| `$root`                                                                    | 项目根目录(COLMAP/OpenMVS/工具都在这下面)               | **你填** |
| `$objs`                                                                    | SAM3 文本提示词列表;下标 0 对应类别 1,下标 1 对应类别 2 | **你填** |
| `$scene` | 工作目录名,不同场景互不干扰 | `$objs[0]`                      |                                                         |                |
| `$IMG` | 原始照片目录 | `$root\data\$scene`                              |                                                         |                |
| `$W` | 场景工作目录 | `$root\work\$scene`                                |                                                         |                |
| `$masks` | SAM3 mask 输出(一张索引图里含所有类别) | `$root\masks_$scene` |                                                         |                |
| `$out` | 成品/中间结果 | `$root\out`                                     |                                                         |                |
| `$names`                                                                   | 逗号拼接的提示词,给 `--text` / `--class-names`      | `cup,bottle` |
| `$cutouts`                                                                 | 每个物体的白底抠图目录                                  | 见上面的循环   |

> `$objs` 里的词会同时当目录名用,别带空格、斜杠、冒号,用英文。
> 拍照的物体叫 `building`、但数据文件夹叫 `food` 时:
> `$objs = @("building")`,`$scene = "food"`。

**换物体/换项目**:改 `$root` 和 `$objs`(必要时再改 `$scene`),从第 2 节重跑;
同一个场景换物体(比如从 `cup` 换成 `table`)只需改 `$objs` 并从第 4 节重跑。

**每开一个新终端都要重新执行这个代码块。**

## 2. COLMAP:特征 → 匹配 → SfM → 去畸变

```powershell
New-Item -ItemType Directory -Force -Path "$W\sparse","$W\dense","$MVS" | Out-Null
```

### ① 特征提取

```powershell
colmap feature_extractor `
  --database_path "$W\db.db" --image_path "$IMG" `
  --ImageReader.single_camera 1 `
  --FeatureExtraction.use_gpu 0 `
  --FeatureExtraction.max_image_size 2000 `
  --SiftExtraction.max_num_features 16384 `
  --SiftExtraction.peak_threshold 0.004
```

- `use_gpu 0` 必须显式写,nocuda 版默认值仍是 1。
- 这一条要求所有照片尺寸一致;混进竖拍图会报 `CAMERA_SINGLE_DIM_ERROR`。
- 后两个参数比 COLMAP 官方默认(`8192` / `0.00667`)宽松,弱纹理桌面物体
  能多提一些特征。想恢复官方值就删掉这两行。

### ② 匹配

```powershell
colmap exhaustive_matcher --database_path "$W\db.db" --FeatureMatching.use_gpu 0 `
  --SiftMatching.max_ratio 0.85 --SiftMatching.max_distance 0.8 `
  --TwoViewGeometry.min_num_inliers 8
```

照片多于 200 张时改用:

```powershell
colmap sequential_matcher --database_path "$W\db.db" `
  --FeatureMatching.use_gpu 0 --SequentialMatching.overlap 10 `
  --SiftMatching.max_ratio 0.85 --SiftMatching.max_distance 0.8 `
  --TwoViewGeometry.min_num_inliers 8
```

这三个匹配参数同样比官方默认(`0.8` / `0.7` / `15`)宽松。

### ③ 稀疏重建

```powershell
colmap mapper --database_path "$W\db.db" --image_path "$IMG" --output_path "$W\sparse" `
  --Mapper.init_min_num_inliers 50 `
  --Mapper.abs_pose_min_num_inliers 15 `
  --Mapper.abs_pose_min_inlier_ratio 0.15 `
  --Mapper.filter_max_reproj_error 6 `
  --Mapper.tri_min_angle 0.5
colmap model_analyzer --path "$W\sparse\0"
```

这五个参数比官方默认(`100` / `30` / `0.25` / `4` / `1.5`)宽松,注册不上的
图会更多。代价是位姿精度略降;如果发现模型明显歪了,把 `filter_max_reproj_error`
调回 `4`、`tri_min_angle` 调回 `1.5` 再跑。

看 `Registered images`。**不是每张照片都能注册**,原因见第 11 节坑 1。
下面的步骤只用注册上的那些图。

如果 `$W\sparse\` 下出现 `0`、`1`、`2` 多个目录,选注册图像最多的那个。
`images.bin` 前 8 个字节就是注册图像数,用 PowerShell 直接读:

```powershell
Get-ChildItem "$W\sparse" -Directory | ForEach-Object {
    $n = [BitConverter]::ToUInt64([IO.File]::ReadAllBytes("$($_.FullName)\images.bin"), 0)
    "{0}: {1} 张" -f $_.Name, $n
}
```

把后文的 `$W\sparse\0` 换成张数最多的编号。`run_pipeline.sh` 会自动选最多的
那个子模型,手工执行时别忘了这一步。

### ④ 去畸变

```powershell
colmap image_undistorter `
  --image_path "$IMG" --input_path "$W\sparse\0" `
  --output_path "$W\dense" --output_type COLMAP
```

产物:

| 路径                 | 内容                                  |
| -------------------- | ------------------------------------- |
| `$W\dense\images\` | **去畸变图**(尺寸会变)          |
| `$W\dense\sparse\` | 位姿,自动选视角、打标签、画相机都用它 |

> **SAM3 必须跑在去畸变图上**,坐标才能和 COLMAP 位姿对上。原图和去畸变图
> 尺寸不同,不能混用。

## 4. SAM3:一次分割多个物体

```powershell
& $sam "$root\tools\sam3_masks.py" `
  --images "$W\dense\images" --out $masks `
  --text $names `
  --overlay-dir "$out\sam_overlay_$scene" `
  --save-json "$out\${scene}_sam.json"
```

- `--text` 里的逗号会被脚本拆成多个概念,顺序就是类别 id:
  `cup,bottle` → 1=cup,2=bottle。也可以重复写 `--text cup --text bottle`,等价。
- `--expect-size W H` 可选;填了就硬校验去畸变图尺寸,防止误指到原图目录。
- 默认跳过已有 mask;**改了提示词/类别数后一定要加 `--overwrite`**
  (或先删 `$masks`),否则会继续用旧 mask。旧 mask 只有一个类别时,下游
  `--class-id 2` 会报「mask 里没有类别 2」。

**先看叠加图** `$out\sam_overlay_$scene\*.png`:不同类别是不同颜色,
确认每个颜色都完整盖住对应物体、没有带进背景。叠加图不对就不要往下跑。

> SAM3 的 `--text` 和后面的 `--class-names` 必须**顺序一致**。

## 5. mask → 点云标签

```powershell
& $py "$root\tools\mask_to_points.py" `
  --scene "$W\dense\sparse" `
  --mask-dir $masks --mask-mode index `
  --class-names $names --min-conf 0.9 `
  --out "$out\${scene}_masked.ply" `
  --out-all "$out\${scene}_all_labeled.ply" `
  --labels "$out\${scene}_labels.npy" `
  --save-npz "$out\${scene}_full.npz" `
  --save-json "$out\${scene}_stats.json"
```

- `--mask-mode index`:SAM3 输出的是索引图,像素值就是类别 id。
- `--min-conf 0.9`:只要多视角一致率 ≥ 90% 的点,压掉 mask 边界抖动。
- `--class-names` 的顺序必须和 SAM3 的 `--text` 一致。

产物 `$out\${scene}_labels.npy` 与点云同序,每个点一个 int32 类别
(0=背景,1=`$objs[0]`,2=`$objs[1]`,...)。

## 6. 白底抠图:每个物体一个目录

```powershell
for ($i = 0; $i -lt $objs.Count; $i++) {
    $o = $objs[$i]; $cid = $i + 1
    & $py "$root\tools\mask_cutout.py" `
      --images "$W\dense\images" --masks $masks `
      --class-id $cid --out $cutouts[$o] --size 1024 --pad 0.08
}
```

每张图裁到该物体的外接框、四周留 8% 白边、补正方形、缩到 1024。
产物:`$cutouts[$o]\*.jpg` + `*_mask.png` + `report.json`。

- 只有一个物体时目录仍是 `$out\${scene}_cutouts`。
- 默认跳过已有 jpg;**重跑过 SAM3(尤其是类别数变了)后要加 `--overwrite`**,
  否则旧的类别 1 抠图会一直留着,和新的 mask 对不上。
- 看每个 `report.json` 里的 `touches_border`:有 `true` 说明该物体被裁掉了一部分,
  调大 `--pad` 重跑(加 `--overwrite`)。
- 某张图里没有某个物体时,该目录下就没有这张图;选视角时会自动跳过它,
  **不会**拿原图顶替。

## 7. 按相机位姿自动选 front/left/right/back

照片是绕物体拍的时候,COLMAP 已经知道每张相机的位姿,不用手工猜方位。

### 原理

1. 读 `dense\sparse\images.bin`,算相机中心 `C = -Rᵀ t`;
2. 用点云最大平面的法向当 up;
3. 用 `$out\${scene}_labels.npy` 里**该类别**的质心当物体中心 `O`;
4. 把 `C-O` 投影到水平面,算每张图的方位角;
5. 穷举「哪张当 front、其余怎么分给 left/right/back」,按下式打分:
   **综合代价 = 方位 RMS(度)+ `--size-weight` × (1 − 平均图片质量)**。
   图片质量由「目标占照片的比例」和「是否贴边被裁」决定,所以会同时
   考虑角度、物体大小和完整性,不会为了 1° 的角度差去选一张目标很小的图。

左/右约定:**+90° = 物体左侧**(相机在物体左边)。

### 命令(每个物体各跑一次)

```powershell
for ($i = 0; $i -lt $objs.Count; $i++) {
    $o = $objs[$i]; $cid = $i + 1
    & $py "$root\tools\colmap_views.py" `
      --model "$W\dense\sparse" `
      --class-id $cid --cutouts $cutouts[$o] `
      --out "$out\${scene}_views_$o.json" `
      --preview "$out\${scene}_${o}_views_preview.jpg"
}
```

输出形如(cup 实测):

```
视角            相对front      误差      俯仰     覆盖率     质量  图片
front           +0.0°    0.0°   34.9°   1.68%   0.76  xxxx.jpg
left          +103.2°   13.2°   42.1°   1.97%   0.89  xxxx.jpg
right          -81.1°    8.9°   44.7°   1.77%   0.80  xxxx.jpg
back          +159.6°   20.4°   44.6°   2.22%   1.00  xxxx.jpg
误差       RMS 12.9°, max 20.4°  | 综合代价 15.0(图片质量 0.86)
```

- 覆盖率 = 物体像素 / 原照片像素;质量 = 覆盖率归一化后再按贴边打折。
- `--size-weight` 默认 15(单位:度):面积翻倍大约能抵 7.5° 方位误差。
  - 想严格按角度:`--size-weight 0`
  - 更看重「物体大而完整」:`--size-weight 30`
- 目标贴到画面边缘(`touches_border`)的照片质量打五折;
  可用 `--border-penalty 0` 关掉这个惩罚。

**提交前先看预览图** `$out\${scene}_${o}_views_preview.jpg`。

常用开关:

| 需求               | 参数                                       |
| ------------------ | ------------------------------------------ |
| 固定某张当 front   | `--front-image 文件名`                   |
| 左右反了           | `--swap-left-right`                      |
| 没有 labels / 点云 | 自动退回相机光轴交点,up 用 `--up camera` |
| 精确指定物体中心   | `--center x,y,z`                         |
| 只要角度、不看大小 | `--size-weight 0`                        |
| 更偏向大图         | `--size-weight 30`                       |

> 视角标签只是方位提示,接口不校验角度。照片没覆盖到 180° 时,
> `back` 会选最接近的那张,误差列会标出来。

## 8. 提交混元多视角生 3D(每个物体一个任务)

### 先 dry-run,不花钱

```powershell
for ($i = 0; $i -lt $objs.Count; $i++) {
    $o = $objs[$i]; $cid = $i + 1
    & $py "$root\tools\img_to_3d.py" `
      --pro --colmap-model "$W\dense\sparse" --dry-run `
      --class-id $cid --cutouts $cutouts[$o] `
      --views-json "$out\${scene}_views_$o.json" `
      --views-preview "$out\${scene}_${o}_views_preview.jpg"
}
```

dry-run 会选图、编码、打印每张图的 base64 大小和最终 payload,**不调用 API**。
逐个确认每个物体的选图正确、所有图 base64 合计 ≤ 6 MB。

### 正式提交(每个物体各扣一次积分)

```powershell
$jobs = @{}
$glbs = @{}
for ($i = 0; $i -lt $objs.Count; $i++) {
    $o = $objs[$i]; $cid = $i + 1
    & $py "$root\tools\img_to_3d.py" `
      --pro --model-version 3.0 --colmap-model "$W\dense\sparse" `
      --class-id $cid --cutouts $cutouts[$o] `
      --views-json "$out\${scene}_views_$o.json"

    $job = Get-ChildItem "$root\work\img2_3d" -Directory |
           Where-Object { $_.Name -match '^\d+$' } |
           Sort-Object LastWriteTime -Descending | Select-Object -First 1
    $glb = Get-ChildItem $job.FullName -Recurse -Filter *.glb |
           Select-Object -First 1
    if (-not $glb) { throw "$o 没找到 glb:$($job.FullName)" }
    $jobs[$o] = $job.FullName
    $glbs[$o] = $glb.FullName
    "类别 $cid = $o  →  JobId $($job.Name)  $($glb.Name)"
}
```

> **每行会扣积分。** 两个物体就是两个任务,先各自 dry-run 确认。
> 跑完把 `$jobs` / `$glbs` 打印出来,确认「哪个 JobId 对应哪个物体」。

3.1 支持斜前视角(最多 8 个视图),循环里给 `img_to_3d.py` 加:

```powershell
--model-version 3.1 `
--auto-view-types front,left_front,left,right_front,right,back
```

### 产物

```
$root\work\img2_3d\<JobId>\
├── response_submit.json
├── response_query.json
├── *.glb                 带贴图的模型
└── *_0\                  obj + mtl + texture png
```

JobId 24 小时内有效。每个物体的 `*.glb` 就是下一步要配准的模型。

## 9. 配准 + 合并显示(支持多个物体 + 相机位姿)

### 命令

```powershell
$meshArgs = @()
for ($i = 0; $i -lt $objs.Count; $i++) {
    $o = $objs[$i]; $cid = $i + 1
    if (-not $glbs.ContainsKey($o)) { throw "没有 $o 的模型,先跑第 8 节" }
    $meshArgs += @("--mesh", "$cid=$($glbs[$o])")
}
$meshArgs

& $py "$root\tools\register_model_to_cloud.py" `
  --cloud "$MVS\scene_dense.ply" `
  --labels "$out\${scene}_labels.npy" `
  --npz "$out\${scene}_full.npz" `
  @meshArgs `
  --mode object --up-axis auto `
  --colmap-model "$W\dense\sparse" `
  --out-merged "$out\${scene}_registered.ply" `
  --save-transform "$out\${scene}_registration.json" `
  --screenshot "$W\register.png"
```

- `--mesh 1=xxx.glb --mesh 2=yyy.glb`:类别 id 必须和 labels 里的一致。
  只有一个物体时也可以直接写 `--mesh $glb.FullName`(走 `--class-id`,默认 1)。
- `@meshArgs` 是 PowerShell 的数组展开,等价于把上面拼好的 `--mesh ...` 逐项写出来。
- **相机位姿**:`--colmap-model` 指向 `dense\sparse`,窗口里会给每张照片画一个
  黄色四棱锥(顶点=相机中心,底面朝物体)。不写也会自动从
  `$MVS\scene_dense.ply` 推 `$W\dense\sparse`;不想看加 `--no-cameras`。
  四棱锥大小用 `--camera-scale 0.05`(场景对角线的比例)调。
- 每个物体的点云会染成不同颜色:类别 1 青色、类别 2 橙色、类别 3 品红…
  其余点保留点云原始照片色。

### 选对模式:建筑还是独立物体

|            | 建筑 / 立面                    | 桌面小物、独立物体          |
| ---------- | ------------------------------ | --------------------------- |
| `--mode` | `facade`(默认)               | `object`                  |
| up 轴      | `y-down`(默认,相机 up = −Y) | `auto`(拟合桌面/地面法向) |
| yaw 搜索   | ±20°                         | 360°                       |
| 打分       | 立面投影轮廓 F1                | 3D 对称 Chamfer             |
| 尺度       | 立面宽度比                     | 包围盒最大边长比            |
| 深度对齐   | 沿 Y 贴立面                    | 不做                        |

**命令行里写的是 `object` 时,`--up-axis auto` 基本都要跟着加。**
反过来,建筑场景不要用 `auto`:建筑点云的最大平面是墙,不是地面。

如果 `auto` 拟合到了错误的平面,可以把第 7 节打印的平面法向直接传进去:

```powershell
--up-axis 0.025,0.520,0.854
```

### 点云颜色

默认 `--cloud-colors keep`:目标类别各自染色,**其余点保留 OpenMVS 重建出来的
照片颜色**(桌面、墙面、背景都是真实色彩),窗口和合并 ply 一致。
只想看几何、不要照片色时加 `--cloud-colors gray`。

> 点云本身没有颜色时,`keep` 会自动退回灰色,并打印一行提示。

### 产物

| 文件                                | 内容                                                                                                                       |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `$out\${scene}_registered.ply`    | **合并点云**:前 N 个是场景点(类别 1 青色、类别 2 橙色、其余保留照片色),后面每个模型各 200,000 个采样点(保留贴图颜色) |
| `$out\${scene}_registration.json` | 每个物体的 scale、4×4 变换、指标,以及 `cameras`(相机中心坐标)                                                           |
| `$W\register.png`                 | 窗口同款截图(含黄色相机四棱锥)                                                                                             |

合并 ply 在 MeshLab / CloudCompare 里打开,两套点交错在一起;点云顺序没变,
`labels.npy` 仍然对得上。多物体时 `registration.json` 的 `objects` 数组里
每一项对应一个类别。

窗口操作:左键旋转、滚轮缩放、中键平移、`Q` 退出。
窗口默认**全量显示、不降采样**;点云太密把模型盖住时加 `--display-voxel -1`
(按目标最大边长 1/100 自动)或 `--display-voxel 0.01`(手动体素)。
不想弹窗加 `--no-show`;不想合并模型采样点加 `--no-merge-mesh`。

### 调参

| 现象                 | 做法                                                             |
| -------------------- | ---------------------------------------------------------------- |
| 尺度太大/太小        | `--scale 1.2` 手动指定(注意:会作用到所有物体)                  |
| 某个方向特别不准     | `--scale-axis x/y/z/max`                                       |
| 朝向还差一点         | `--yaw-step 5` 细化;或 `--yaw-range 20` 只搜小范围           |
| 模型没立正           | 检查 `--up-axis`;桌面物体用 `auto`                           |
| 窗口里点云把模型盖住 | `--display-offset 0.012`(只影响显示)                           |
| 配准滑到一边         | 建筑用默认 `facade`;独立物体用 `object`,不要开 `--use-icp` |
| 相机四棱锥太小/太大  | `--camera-scale 0.03` / `0.1`                                |
| 不想看相机           | `--no-cameras`                                                 |

## 11. 坑

| #  | 现象                       | 原因                                                                                                    | 解决                                                                                             |
| -- | -------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 1  | 照片没有全部注册           | 纹理重复、目标占画面太小、相邻图重叠不足;mapper 只保留最大的连通块                                      | 已放宽阈值(见第 2 节);仍不够就让目标占画面更大、背景放点纹理、多拍重叠。多个子模型时用张数最多的 |
| 2  | 目标只有几百个点           | 深色/反光物体在稠密点云里本来就稀;mask 投影还会带上目标后面的背景点                                     | 正常。配准工具在标注点 < 1000 时自动跳过统计滤波                                                 |
| 3  | 尺度明显偏小               | 统计滤波把稀疏的目标点删了,包围盒塌掉                                                                   | 已按点数自动跳过;仍不对就 `--scale` 手动给                                                     |
| 4  | 模型躺着                   | 用了建筑的 Y-down 假设                                                                                  | 桌面物体加 `--up-axis auto`                                                                    |
| 5  | 配准沿一个方向滑走         | `facade` 模式假设只有正立面                                                                           | 独立物体改用 `--mode object`                                                                   |
| 6  | 混元报 `ViewType` 不支持 | 1804 只有 `left/right/back`(+3.1 的 `top/bottom/left_front/right_front`),**没有 `unknown`** | 用相机位姿算出的近似标签                                                                         |
| 7  | 视角角度对不上             | 照片不是每 90° 一张                                                                                    | 标签只是方位提示,误差列已打印                                                                    |
| 8  | 提交报 Base64 超限         | 所有图 base64 合计 ≤ 6 MB                                                                              | 抠图统一到 1024,一般远低于上限                                                                   |
| 9  | 积分被扣了才发现选图错     | 除 `--dry-run` 外都会真扣                                                                             | 永远先 dry-run 看预览图                                                                          |
| 10 | `SecretKey.csv` 被提交   | 忘了 gitignore                                                                                          | 永远不要 `git add -f`                                                                          |
| 11 | 第二个物体选图用了原图     | 旧版在缺抠图时逐张退回原图                                                                              | 已改:抠图目录存在时,缺图=这张没检测到,直接跳过                                                   |
| 12 | 两个物体配准串色           | 两个 `labels` 类别混在一起                                                                            | 每个 `--mesh` 前写类别 id:`2=xxx.glb`                                                        |
| 13 | 窗口里看不到相机           | 没找到 `images.bin`                                                                                   | 显式加 `--colmap-model "$W\dense\sparse"`                                                      |
| 14 | 第二个物体整类为空         | 所有提示词被当成一个概念(逗号没拆开),mask 里永远只有类别 1                                              | 已修:逗号会自动拆;仍为空就换提示词并加 `--overwrite`                                           |

## 12. 换项目 / 换物体

### 换整个项目

只改 `$root`,然后从头跑:

```powershell
$root = "E:\some\other\project"
$objs = @("chair")
$scene = $objs[0]
$IMG = "$root\data\$scene"
```

要求新项目里有同样的 `tools\`、`OpenMVS_Windows_x64\`、`data\` 布局。
`$py` / `$sam` 不用改。

### 同一组照片,换分割物体

只改 `$objs`(必要时 `$scene`),从第 4 节重跑:

```powershell
$objs = @("table")
$names = $objs -join ","
& $sam ... --text $names --out "$root\masks_$scene" ...
& $py ... --class-names $names ...
```

第 2、3 节的 COLMAP/OpenMVS 结果可以复用,**不要重跑**。

### 只想重新选视角

```powershell
for ($i = 0; $i -lt $objs.Count; $i++) {
    $o = $objs[$i]; $cid = $i + 1
    & $py "$root\tools\colmap_views.py" --model "$W\dense\sparse" `
      --class-id $cid --cutouts $cutouts[$o] `
      --preview "$out\${scene}_${o}_views_preview.jpg"
}
```

### 只想重新配准

直接跑第 9 节;`$jobs` / `$glbs` 需要在当前终端里已有(第 8 节会填)。
新终端里重跑第 0 节,再按 JobId 手工指定 `--mesh`:

```powershell
--mesh "1=$root\work\img2_3d\<JobId1>\xxx.glb" `
--mesh "2=$root\work\img2_3d\<JobId2>\yyy.glb"
```
