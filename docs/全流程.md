
# 全流程:照片 → 点云 → SAM 分割 → 多视角生 3D → 配准叠加

从一组绕物体拍的照片,一直做到「生成的模型和重建点云在同一个 Open3D 窗口里」。
命令全是 PowerShell,适用于任意项目路径、任意物体。

**你只需要在开头改两行:项目根目录、SAM 要分割的物体名称。**

```
<照片目录>\*.jpg
    │  ①-⑤ COLMAP               SIFT → 匹配 → SfM → 去畸变
    ▼
<root>\work\<场景>\dense\        去畸变图 + 位姿
    │  ⑥-⑧ OpenMVS             转工程 → 稠密点云 → 网格
    ▼
<root>\work\<场景>\mvs\scene_dense.ply
    │  ⑨-⑩ SAM3 + mask_to_points
    ▼
<root>\out\<场景>_labels.npy     每个点一个类别
    │  ⑪ mask_cutout            白底抠图
    ▼
<root>\out\<场景>_cutouts\*.jpg
    │  ⑫ colmap_views.py        按相机位姿自动选 front/left/right/back
    ▼
<root>\out\<场景>_views.json
    │  ⑬ img_to_3d.py --pro     混元多视角生 3D
    ▼
<root>\work\img2_3d\<JobId>\*.glb
    │  ⑭ register_model_to_cloud.py
    ▼
<root>\out\<场景>_registered.ply + Open3D 窗口
```

## 0. 开头只改这里

```powershell
# ===================== 只改这两行 =====================
$root = "D:\code\point_cloud\0916"   # 项目根目录
$obj  = "cup"                         # SAM3 的物体名称,也是默认场景名
# ======================================================

# 场景名:默认跟物体名一致;数据文件夹叫别的名字时改这一行
$scene = $obj

# 图片目录:默认 <root>\data\<场景>;照片在别处时改这一行
$IMG = "$root\data\$scene"

# ---- 下面都是推导出来的,不用改 ----
$py    = "C:\Users\FANLS\.conda\envs\basic_env\python.exe"
$sam   = "D:\ProgramData\anaconda3\envs\sam3\python.exe"
$W     = "$root\work\$scene"
$MVS   = "$W\mvs"
$masks = "$root\masks_$scene"
$out   = "$root\out"
```

| 变量                                                 | 含义                                      | 默认值         |
| ---------------------------------------------------- | ----------------------------------------- | -------------- |
| `$root`                                            | 项目根目录(COLMAP/OpenMVS/工具都在这下面) | **你填** |
| `$obj`                                             | SAM3 的文本提示,对应类别 id 1             | **你填** |
| `$scene` | 工作目录名,不同场景互不干扰 | `$obj`  |                                           |                |
| `$IMG` | 原始照片目录 | `$root\data\$scene`      |                                           |                |
| `$W` | 场景工作目录 | `$root\work\$scene`        |                                           |                |
| `$masks` | SAM3 mask 输出 | `$root\masks_$scene` |                                           |                |
| `$out` | 成品/中间结果 | `$root\out`             |                                           |                |

> `$obj` 会同时当目录名用,别带空格、斜杠、冒号。拍照的物体叫 `building`,
> 但数据文件夹叫 `food` 时:`$obj = "building"`,`$scene = "food"`。

**换物体/换项目**:只改 `$root` 和 `$obj`(必要时再改 `$scene`),从第 2 节重跑;
同一个场景换物体(比如从 `cup` 换成 `table`)只需改 `$obj` 并从第 4 节重跑。

**每开一个新终端都要重新执行这个代码块。**

## 2. COLMAP:特征 → 匹配 → SfM → 去畸变

```powershell
New-Item -ItemType Directory -Force -Path "$W\sparse","$W\dense","$MVS" | Out-Null
```

### ① 特征提取

```powershell
colmap feature_extractor `
  --database_path "$W\db.db" --image_path "$IMG" `
  --ImageReader.single_camera 1 `
  --FeatureExtraction.use_gpu 0 `
  --FeatureExtraction.max_image_size 2000
```

- `use_gpu 0` 必须显式写,nocuda 版默认值仍是 1。
- 这一条要求所有照片尺寸一致;混进竖拍图会报 `CAMERA_SINGLE_DIM_ERROR`。

### ② 匹配

```powershell
colmap exhaustive_matcher --database_path "$W\db.db" --FeatureMatching.use_gpu 0
```

照片多于 200 张时改用:

```powershell
colmap sequential_matcher --database_path "$W\db.db" `
  --FeatureMatching.use_gpu 0 --SequentialMatching.overlap 10
```

### ③ 稀疏重建

```powershell
colmap mapper --database_path "$W\db.db" --image_path "$IMG" --output_path "$W\sparse"
colmap model_analyzer --path "$W\sparse\0"
```

看 `Registered images`。**不是每张照片都能注册**,原因见第 11 节坑 1。
下面的步骤只用注册上的那些图。

如果 `$W\sparse\` 下出现 `0`、`1`、`2` 多个目录,选注册图像最多的那个,
把后文的 `$W\sparse\0` 换成对应编号。

### ④ 去畸变

```powershell
colmap image_undistorter `
  --image_path "$IMG" --input_path "$W\sparse\0" `
  --output_path "$W\dense" --output_type COLMAP
```

产物:

| 路径                 | 内容                          |
| -------------------- | ----------------------------- |
| `$W\dense\images\` | **去畸变图**(尺寸会变)  |
| `$W\dense\sparse\` | 位姿,自动选视角和打标签都用它 |

> **SAM3 必须跑在去畸变图上**,坐标才能和 COLMAP 位姿对上。原图和去畸变图
> 尺寸不同,不能混用。

## 3. OpenMVS:工程 → 稠密点云 → 网格

```powershell
cd $MVS
```

### ⑤ 转 OpenMVS 工程

```powershell
InterfaceCOLMAP -i "$W\dense" -o "$MVS\scene.mvs" `
  --image-folder "$W\dense\images" -w "$MVS"
```

### ⑥ 稠密点云

```powershell
DensifyPointCloud scene.mvs --resolution-level 1 --max-resolution 2000 --number-views 8
```

`--number-views` 不能超过注册图像数,图少时调小。
产物 `scene_dense.ply`,这是后面所有步骤的点云。

### ⑦ 网格(给 mask_to_points 做遮挡用)

```powershell
ReconstructMesh scene_dense.mvs -p scene_dense.ply -o scene_dense_mesh.ply
```

> **`-p` 是输入点云,不是输出网格。** 写成 `-p scene_dense_mesh.ply` 会静默退回
> 稀疏点。跑完看日志里 `Point-cloud '...' loaded:` 的点数是不是稠密点云的量级。

这条流程不需要 `TextureMesh`;要看重建贴图模型再单独跑。

## 4. SAM3:把物体抠出来

```powershell
& $sam "$root\tools\sam3_masks.py" `
  --images "$W\dense\images" --out $masks `
  --text $obj `
  --overlay-dir "$out\sam_overlay_$scene" `
  --save-json "$out\${scene}_sam.json"
```

- `--expect-size W H` 可选;填了就硬校验去畸变图尺寸,防止误指到原图目录。
  尺寸从 `$W\dense\images` 里任意一张读。
- 默认跳过已有 mask,断了重跑会接着走;要重来加 `--overwrite`。

**先看叠加图** `$out\sam_overlay_$scene\*.png`,确认青色区域完整盖住目标、
没有带进背景。叠加图不对就不要往下跑,下游很难归因。

> SAM3 的 `--text` 和后面的 `--class-names` 必须一致,类别 id 从 1 开始。

## 5. mask → 点云标签

```powershell
& $py "$root\tools\mask_to_points.py" `
  --scene "$W\dense\sparse" `
  --mask-dir $masks --mask-mode index `
  --class-names $obj --min-conf 0.9 `
  --out "$out\${scene}_masked.ply" `
  --out-all "$out\${scene}_all_labeled.ply" `
  --labels "$out\${scene}_labels.npy" `
  --save-npz "$out\${scene}_full.npz" `
  --save-json "$out\${scene}_stats.json"
```

- `--mask-mode index`:SAM3 输出的是索引图,像素值就是类别 id。
- `--min-conf 0.9`:只要多视角一致率 ≥ 90% 的点,压掉 mask 边界抖动。
- `--class-names` 的顺序必须和 SAM3 的 `--text` 一致。

产物 `$out\${scene}_labels.npy` 与点云同序,每个点一个 int32 类别
(0=背景,1=`$obj`)。点云里物体越小,标注点越少,这是正常的。

## 6. 白底抠图(混元的输入)

```powershell
& $py "$root\tools\mask_cutout.py" `
  --images "$W\dense\images" --masks $masks `
  --out "$out\${scene}_cutouts" --size 1024 --pad 0.08
```

每张图裁到目标外接框、四周留 8% 白边、补正方形、缩到 1024。
产物:`$out\${scene}_cutouts\*.jpg` + `*_mask.png` + `report.json`。

看 `report.json` 里的 `touches_border`:有 `true` 说明物体被裁掉了一部分,
调大 `--pad` 重跑(加 `--overwrite`)。

## 7. 按相机位姿自动选 front/left/right/back

照片是绕物体拍的时候,COLMAP 已经知道每张相机的位姿,不用手工猜方位。

### 原理

1. 读 `dense\sparse\images.bin`,算相机中心 `C = -Rᵀ t`;
2. 用点云最大平面的法向当 up;
3. 用 `$out\${scene}_labels.npy` 里目标类别的质心当物体中心 `O`;
4. 把 `C-O` 投影到水平面,算每张图的方位角;
5. 穷举「哪张当 front、其余怎么分给 left/right/back」,选方位误差最小的一组。

左/右约定:**+90° = 物体左侧**(相机在物体左边)。

### 命令

```powershell
& $py "$root\tools\colmap_views.py" `
  --model "$W\dense\sparse" `
  --out "$out\${scene}_views.json" `
  --preview "$out\${scene}_views_preview.jpg"
```

输出形如:

```
视角            相对front      误差      俯仰     覆盖率  图片
front           +0.0°    0.0°   34.9°   1.68%  xxxx.jpg
left          +103.1°   13.1°   42.1°   1.97%  xxxx.jpg
right          -81.1°    8.9°   44.7°   1.77%  xxxx.jpg
back          +159.6°   20.4°   44.6°   2.22%  xxxx.jpg
误差       RMS 12.9°,max 20.4°
```

默认路径都能从 `--model` 推出来:

```
$W\dense\sparse     →  场景名 <scene>
    ├── $out\<scene>_cutouts
    ├── $out\<scene>_labels.npy
    └── $MVS\scene_dense.ply
```

**提交前先看预览图** `$out\${scene}_views_preview.jpg`。

常用开关:

| 需求               | 参数                                       |
| ------------------ | ------------------------------------------ |
| 固定某张当 front   | `--front-image 文件名`                   |
| 左右反了           | `--swap-left-right`                      |
| 没有 labels / 点云 | 自动退回相机光轴交点,up 用 `--up camera` |
| 精确指定物体中心   | `--center x,y,z`                         |

> 视角标签只是方位提示,接口不校验角度。照片没覆盖到 180° 时,
> `back` 会选最接近的那张,误差列会标出来。

## 8. 提交混元多视角生 3D

### 先 dry-run,不花钱

```powershell
& $py "$root\tools\img_to_3d.py" `
  --pro --colmap-model "$W\dense\sparse" --dry-run `
  --views-json "$out\${scene}_views.json" `
  --views-preview "$out\${scene}_views_preview.jpg"
```

dry-run 会选图、编码、打印每张图的 base64 大小和最终 payload,**不调用 API**。
确认选图正确、所有图 base64 合计 ≤ 6 MB。

### 正式提交(4 视图)

```powershell
& $py "$root\tools\img_to_3d.py" `
  --pro --model-version 3.0 --colmap-model "$W\dense\sparse"
```

> **这一行会扣积分。** 只有确认 dry-run 的选图没问题再跑。

3.1 支持斜前视角(最多 8 个视图):

```powershell
& $py "$root\tools\img_to_3d.py" `
  --pro --model-version 3.1 --colmap-model "$W\dense\sparse" `
  --auto-view-types front,left_front,left,right_front,right,back
```

### 产物


## 9. 配准 + 合并显示

### 命令

自动取**最近一次**混元任务(刚提交完就是当前这个):

```powershell
$job = Get-ChildItem "$root\work\img2_3d" -Directory |
       Where-Object { $_.Name -match '^\d+$' } |
       Sort-Object LastWriteTime -Descending | Select-Object -First 1
if (-not $job) { throw "没有混元任务,先跑第 8 节" }

$glb = Get-ChildItem $job.FullName -Recurse -Filter *.glb | Select-Object -First 1
if (-not $glb) { throw "没找到 glb:$($job.FullName)" }

& $py "$root\tools\register_model_to_cloud.py" `
  --cloud "$MVS\scene_dense.ply" `
  --labels "$out\${scene}_labels.npy" `
  --npz "$out\${scene}_full.npz" `
  --mesh $glb.FullName `
  --mode object --up-axis auto `
  --out-merged "$out\${scene}_registered.ply" `
  --save-transform "$out\${scene}_registration.json" `
  --screenshot "$W\register.png"
```

指定某个历史任务时,把 `--mesh` 换成:

```powershell
--mesh "$root\work\img2_3d\<JobId>\<文件名>.glb"
```

### 选对模式:建筑还是独立物体

|            | 建筑 / 立面                    | 桌面小物、独立物体          |
| ---------- | ------------------------------ | --------------------------- |
| `--mode` | `facade`(默认)               | `object`                  |
| up 轴      | `y-down`(默认,相机 up = −Y) | `auto`(拟合桌面/地面法向) |
| yaw 搜索   | ±20°                         | 360°                       |
| 打分       | 立面投影轮廓 F1                | 3D 对称 Chamfer             |
| 尺度       | 立面宽度比                     | 包围盒最大边长比            |
| 深度对齐   | 沿 Y 贴立面                    | 不做                        |

**命令行里写的是 `object` 时,`--up-axis auto` 基本都要跟着加。**
反过来,建筑场景不要用 `auto`:建筑点云的最大平面是墙,不是地面。

如果 `auto` 拟合到了错误的平面,可以把第 7 节打印的平面法向直接传进去:

```powershell
--up-axis 0.025,0.520,0.854
```

### 点云颜色

默认 `--cloud-colors keep`:目标类别染青色,**其余点保留 OpenMVS 重建出来的照片颜色**
(桌面、墙面、背景都是真实色彩),窗口和合并 ply 一致。
只想看几何、不要照片色时加 `--cloud-colors gray`。

> 点云本身没有颜色(OpenMVS 跑了 `--no-colors` 或 ply 是纯几何)时,
> `keep` 会自动退回灰色,并打印一行提示。

### 产物

| 文件                                | 内容                                                                                                              |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `$out\${scene}_registered.ply`    | **合并点云**:前 N 个是场景点(目标类别青色,其余保留点云原始照片色),后面 200,000 个是模型采样点(保留贴图颜色) |
| `$out\${scene}_registration.json` | scale、4×4 变换、up 轴、Chamfer/覆盖率                                                                           |
| `$W\register.png`                 | 窗口同款截图                                                                                                      |

合并 ply 在 MeshLab / CloudCompare 里打开,两套点交错在一起;点云顺序没变,
`labels.npy` 仍然对得上。

窗口操作:左键旋转、滚轮缩放、中键平移、`Q` 退出。
窗口默认**全量显示、不降采样**;点云太密把模型盖住时加 `--display-voxel -1`
(按目标最大边长 1/100 自动)或 `--display-voxel 0.01`(手动体素)。
不想弹窗加 `--no-show`;不想合并模型采样点加 `--no-merge-mesh`。

### 调参

| 现象                 | 做法                                                             |
| -------------------- | ---------------------------------------------------------------- |
| 尺度太大/太小        | `--scale 1.2` 手动指定                                         |
| 某个方向特别不准     | `--scale-axis x/y/z/max`                                       |
| 朝向还差一点         | `--yaw-step 5` 细化;或 `--yaw-range 20` 只搜小范围           |
| 模型没立正           | 检查 `--up-axis`;桌面物体用 `auto`                           |
| 窗口里点云把模型盖住 | `--display-offset 0.012`(只影响显示)                           |
| 配准滑到一边         | 建筑用默认 `facade`;独立物体用 `object`,不要开 `--use-icp` |

## 11. 坑

| #  | 现象                       | 原因                                                                                                    | 解决                                               |
| -- | -------------------------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 1  | 照片没有全部注册           | 纹理重复、目标占画面太小、相邻图重叠不足;mapper 只保留最大的连通块                                      | 不是 bug。让目标占画面更大、背景放点纹理、多拍重叠 |
| 2  | 目标只有几百个点           | 深色/反光物体在稠密点云里本来就稀;mask 投影还会带上目标后面的背景点                                     | 正常。配准工具在标注点 < 1000 时自动跳过统计滤波   |
| 3  | 尺度明显偏小               | 统计滤波把稀疏的目标点删了,包围盒塌掉                                                                   | 已按点数自动跳过;仍不对就 `--scale` 手动给       |
| 4  | 模型躺着                   | 用了建筑的 Y-down 假设                                                                                  | 桌面物体加 `--up-axis auto`                      |
| 5  | 配准沿一个方向滑走         | `facade` 模式假设只有正立面                                                                           | 独立物体改用 `--mode object`                     |
| 6  | 混元报 `ViewType` 不支持 | 1804 只有 `left/right/back`(+3.1 的 `top/bottom/left_front/right_front`),**没有 `unknown`** | 用相机位姿算出的近似标签                           |
| 7  | 视角角度对不上             | 照片不是每 90° 一张                                                                                    | 标签只是方位提示,误差列已打印                      |
| 8  | 提交报 Base64 超限         | 所有图 base64 合计 ≤ 6 MB                                                                              | 抠图统一到 1024,一般远低于上限                     |
| 9  | 积分被扣了才发现选图错     | 除 `--dry-run` 外都会真扣                                                                             | 永远先 dry-run 看预览图                            |
| 10 | `SecretKey.csv` 被提交   | 忘了 gitignore                                                                                          | 永远不要 `git add -f`                            |

## 12. 换项目 / 换物体

### 换整个项目

只改 `$root`,然后从头跑:

```powershell
$root = "E:\some\other\project"
$obj  = "chair"
$scene = $obj
$IMG = "$root\data\$scene"
```

要求新项目里有同样的 `tools\`、`OpenMVS_Windows_x64\`、`data\` 布局。
`$py` / `$sam` 不用改。

### 同一组照片,换分割物体

只改 `$obj`(必要时 `$scene`),从第 4 节重跑:

```powershell
$obj = "table"
& $sam ... --text $obj --out "$root\masks_$scene" ...
& $py ... --class-names $obj ...
```

第 2、3 节的 COLMAP/OpenMVS 结果可以复用,**不要重跑**。

### 只想重新选视角

```powershell
& $py "$root\tools\colmap_views.py" --model "$W\dense\sparse" --preview "$out\${scene}_views_preview.jpg"
```

### 只想重新配准

直接跑第 9 节;`$job` / `$glb` 会取最近一次混元任务。
